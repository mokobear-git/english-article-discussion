# 論文ディスカッション

英語論文と設問を読み込み、次の流れで学ぶ Web アプリ。入力にはスマホの音声入力も使える。

1. 論文の日本語訳を表示(ストリーミング)
2. 設問を1つずつ、選択肢つきのスモールステップ質問で解く
3. 考えをまとめて「こうですか?」と確認。OKで日本語の解答文を提示
4. 解答文を1文ずつ英訳させる。語彙ヒントつき。評価・訂正のうえ確定
5. 次の設問へ。確定した英文は「成果」タブにたまり、Markdown で保存できる

使い方の詳しい説明(APIキーの取得、スマホでの公開手順を含む)は [docs/usage-guide.pdf](docs/usage-guide.pdf) を参照。

## 起動

Node.js 20 以上が必要。

```bash
npm install
```

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

```bash
npm start
```

ブラウザで http://localhost:3000 を開く。

## スマートフォンで使う

スマホから使うには、次のいずれかで https の URL を用意する。

### A. Render に公開する(常時使える)

1. https://render.com にログインし、New → Blueprint を選ぶ。
2. このリポジトリを選ぶ。`render.yaml` の設定が読み込まれる。
3. 環境変数 `ANTHROPIC_API_KEY`(API キー)と `APP_PASSWORD`(アプリのパスワード、任意の文字列)を入力して作成。
4. 発行された `https://〜.onrender.com` をスマホで開く。ユーザー名は空欄または任意、パスワードは `APP_PASSWORD`。

無料プランの注意: 15分間アクセスがないと停止し、次回の起動に数十秒かかる。停止・再デプロイでサーバー側の記録(`data/`)は消える。成果は「Markdownで保存」で手元に残す。

### B. 手元の PC を一時的に公開する

PC で `npm start` したうえで、別のターミナルで次を実行する。表示された `https://〜.trycloudflare.com` をスマホで開く。

```bash
npx cloudflared tunnel --url http://localhost:3000
```

URL を知る人は誰でも使えるため、`APP_PASSWORD` を設定してから起動する。

```bash
APP_PASSWORD=好きなパスワード npm start
```

### ホーム画面に追加

ブラウザの共有メニュー(iPhone: Safari の共有 → ホーム画面に追加、Android: Chrome のメニュー → ホーム画面に追加)でアプリとして起動できる。

### スマホでの動作

- 入力はキーボードの音声入力(マイクボタン)が使える。英語を話すときはキーボードを英語に切り替える。
- 選択肢はスマホでは A・B・C の記号ボタンを横一列に表示する(内容は会話欄で読む)。
- アプリを裏に回すと読み上げを止める。

API キーなしで画面だけ試す場合はモックで起動する。

```bash
npm run mock
```

## 使い方

- 設問は任意。なければ AI が論文から討論用の設問(解釈・意見を問うもの)を 1〜5 個作る(既定 3 個)。
- 論文・設問は PDF・テキスト・画像(png/jpeg/webp/gif)。複数ファイル可。本文の貼り付けも可。Word は PDF に変換して読み込む。
- 最初に表示するものを「全文訳」「要約」「なし」から選ぶ。訳文欄の上部でいつでも切り替えられる。著作権のある記事などで全文訳が適切でないとモデルが判断した場合は、要約が表示される。
- 「開始」で訳文が流れ始める。訳文の表示中に、設問指導の最初の応答を裏で先に生成しておくため、「設問へ進む」を押すとすぐ始まる。
- 「設問へ進む」で入力欄が使えるようになる。回答は入力欄に書いて「送信」(PC では Enter、Shift+Enter で改行)。選択肢はボタンでも回答できる。
- 読み上げは既定で「推奨英文のみ」。英訳を答えた後、確定した推奨英文だけを英語で読み上げる。日本語の問いや選択肢は読み上げない(設定で「応答をすべて」「なし」に変更可)。
- 日本語の解答文は、英訳しやすいよう 1 文 1 内容・おおむね 25 字以内・主語つきの短い文に分けて示す。確定英文もシンプルな英文にする。
- 文字の大きさは設定で変えられる(自動ではスマホで大きめ)。
- 「ヒント」で追加ヒント。「読み上げ停止」または Esc で読み上げ停止。
- 途中でページを閉じても、同じブラウザで開き直せば続きから再開する(記録はサーバーの `data/sessions/` に保存)。

## 応答速度に関する設定

環境変数で調整する。

| 変数 | 既定値 | 内容 |
|---|---|---|
| `MODEL` | `claude-haiku-5-5` | 使用モデル。精度を上げたい場合は `claude-sonnet-5-5` や `claude-opus-5-5` |
| `DIALOG_EFFORT` | `low` | 対話ターンの思考量。`low` が最速 |
| `TRANSLATE_EFFORT` | `medium` | 全文翻訳の思考量 |
| `FAST_MODE` | 未設定 | `1` で Opus の fast モード(Opus 使用時のみ。出力速度最大約2.5倍、料金2倍) |
| `PORT` | `3000` | ポート |
| `APP_PASSWORD` | 未設定 | 設定するとパスワード保護(Basic 認証)を有効にする。公開時は必須 |

速度のための実装上の工夫:

- 応答はすべてストリーミング。画面表示は最初のトークンから始まる(読み上げを「応答をすべて」にした場合は読み上げも同様)。
- 論文・設問はプロンプトキャッシュに載せ、翻訳と全対話ターンで共有する。2ターン目以降の待ち時間が短くなる。
- 対話ターンは短く(3〜6文)返すよう指示している。
- 応答中に送信すると、その応答を中断して新しい入力を処理する。

## 構成

```
server.js      HTTP サーバー、Claude API 呼び出し(ストリーミング)、セッション保存
prompts.js     システムプロンプト(指導手順・METAライン仕様)と各タスク指示
mock.js        MOCK=1 用の疑似応答
public/        画面(index.html / style.css / app.js)、PWA 用 manifest とアイコン
render.yaml    Render へのデプロイ設定
```

- モデルは各応答の末尾に `<<<META {...}>>>` 行(設問番号・段階・選択肢・英訳対象文・確定英文など)を付ける。画面はこの行を表示・読み上げせず、選択肢ボタン、英訳対象カード、成果タブの更新に使う。
- Sonnet / Opus 使用時は、拒否応答(refusal)に備えてサーバー側フォールバック(`fallbacks: "default"`)を有効にする。Haiku には同機能がないため、拒否時はエラー表示となる。

## 注意

- 論文データは Anthropic API に送信される。
